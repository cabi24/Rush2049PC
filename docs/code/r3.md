# r3: the game image from 0x800B4720 to 0x800CD798

Wave 1 of the PC-only work ([PCONLY.md](../port/PCONLY.md)). This page is a map of one slice of the game's code for a
programmer new to it: 244 function symbols (115 of them `func_8…`, 223 renamed), about 400 data symbols they use, and
the original modules they come from. The names are in [tools/port/names/r3.tsv](../../tools/port/names/r3.tsv); this
page uses the new names, with the old one in parentheses where it helps. The MAT3 decomp (the GameCube build of the same
game, with its debug names) is the reference throughout; "MAT3 X" means the function or global of that name there.

## 1. What this part of the game does

Nothing in the slice is one subsystem. It holds the bottom layers that everything else calls, plus several whole
modules:

- **Text and HUD helpers**: the font engine (`HAL_text.c`: `HAL_DrawText`, `DrawText`, colours, positions, widths),
  the text toolbox above it (`TB_text.c`: justification, `TB_DrawText`, `TB_Printf`, word-wrapped scroll boxes,
  flashing colours, two-byte strings), the once-per-frame callback table (`HAL_time.c`), the coin HUD (`animCoins`)
  and the race countdown (`ShowCountdown`).
- **Front-end screens**: the video options screen (`videoscr.c`), the pause screen's clean-up, the front-end
  background (`createBG`/`removeBG`), menu sounds (`PlayUDSound` …).
- **Controls**: pad masks with auto-repeat (`controlsys.c` `UpdateControls`, `ClearControls`) and the per-player copy
  (`controls.c` `UpdateRushControls`); `UpdateFrame` ends a frame and runs them.
- **Tracks, paths and checkpoints**: `LoadTrack`/`UnloadTrack`, the checkpoint and path data (`pathcommon.c`:
  `ReadCheckpointData`, `ReadPathData`, the path/checkpoint intersections, alternate paths, checkpoint times), sky,
  texture/palette animation (`textureanim.c`), the attract-mode start points.
- **Car physics pieces**: the tyre force model (`tires.c`: `dotireforce`, `frictioncircle`, `calcalpha`,
  `calctireuv`) and the world collision code (`stree.c`: `TireSurf`, `CollideCarBody`, `RoadPosition`,
  `CameraCollision`, moving collision objects).
- **Level objects ("targets")**: `targets.c` (set-up, car-versus-target collision, slow-down near objects) and the
  path-following targets (`targetpaths.c`: drawbridges, elevators and the like, with their sounds).
- **Stunts**: `stunt.c` in full (flip, roll, spin, two-wheel and air-time detection, scoring).
- **Respawn helpers**: `SetResurrectionData`, `AbortCar`, the AI path index set-up (`maxpath.c`).
- **Smoke**: `InitSmoke`, `UpdateSmoke` (exhaust and smoke puffs).
- **Audio manager front end**: `AudioInit`/`AudioShutdown`, the 3D listener/emitter pools, song and volume commands,
  emitter updates (`audiomgr.c`), all of them posting commands to the audio thread.
- **Game state**: `updateGameState` (the state machine of the whole game), `setGameState`, the front-end wave and
  overlay loading (`state.c`), `SetOptions` (options to runtime globals).
- **Save data**: most of `save.c` (player profiles, options, car settings, ghosts, the controller-pak server), the
  records' totals (`gamerecords.c`), and the heap's high allocator, reallocation and compaction (`memsys.c`).

## 2. How the image is laid out

The N64 game was compiled as one program (IDO `-O3` with `uld`/`umerge`, [COMPILER_SETTINGS.md](../COMPILER_SETTINGS.md)),
so the functions are not in source-file order. The order is a depth-first post-order of the call graph: a function
comes after its callees, and a caller's callees are visited **last call first**. Two consequences that this map relies
on:

- Runs of one module appear where its functions call each other, and they appear in reverse call order. `CheckForStunt`
  calls `_CheckRoll, _CheckSpin, _CheckFlip, _CheckMulti, _CheckAirTime, _Check2WheelSide, _Check2WheelFront,
  _Check2WheelBack, _AddStunt`; the image holds exactly `_AddStunt, _Check2WheelBack, … _CheckRoll, CheckForStunt`
  (0x800C1B60–0x800C2BE0). The same holds for `SyncCheckpointsToPaths`, `HAL_SetFont`'s semaphore helpers,
  `uninitScreen` and `StartPathTarget`.
- When `umerge` inlines a static function into every caller it deletes it but leaves an 8-byte `jr ra; nop` stub at
  the position the layout gives it. These stubs have no callers; the map names them `<original>_stub` (for example
  `ResetStunts_stub` right before `InitStunt`). Where the decomp gave such a stub the inlined function's body, the
  plain original name is used (`CheckAirTime`, `FreeGhost`, `video_validOption`).

So "modules" below are runs, and one MAT3 file can appear in several places.

## 4. Main data structures

- **`gCheckpoints`** (0x80151CE8, the checkpoint block copied from `gPathWave`): `numPoints`, `loopPt`, `finishPt`,
  `startPt`, `startTime` (90), and 0x50-byte points with position, normal, radius, flags (1 finish, 2 start, 4 loop),
  two section times and `pathPts[20]`: for each checkpoint, where the resurrection path (0), the four drone paths
  (1-4) and the alternate paths (5-19) cross it. `SyncCheckpointsToPaths` fills `pathPts`; `CalcCheckpointTimes` the
  times.
- **`gResPath`** (0x801407F0): the resurrection path `{numPts, pts (s16[3]), numAlt, alt}`; alternate paths carry
  `firstPath/firstIdx/lastPath/lastIdx`, `resurrect` and `startSection`. **`gDronePaths[4]`** (0x8012E5E8): the AI
  paths `{numPts, pts}` with 8-byte points. Several symbols point inside these (`gResPath_pts`, `gResPath_alt`,
  `gCheckpoints_pathPts`, `gDronePaths_pts`): wave 2 should replace them with field accesses.
- **Targets** (`tTarget`, 0x70 bytes, same offsets as MAT3): pool `gTargetList` over `gTargetArray` (130 on the N64),
  per-kind table `targetInfo` (0x80117530: sounds, fade distance, start/animate functions), the collision quadtree
  `gTargetGroups`/`gTargetGroupList`, the six shape tests `gTargetCollFuncPtrs`. Path targets
  (`tTargetStructPath` behind `t->data`) step through keys with position, quaternion, speed and scale;
  `CollisionTargetPtrs` lists those that move world collision geometry.
- **World collision** (`stree.c`): `stree_nodes` (quadtree), `stree_surf` (surfaces with packed s16 orientation),
  `stree_svert` (vertices packed as s16 + three 5-bit fractions, 1/32 units), `stree_slist`/`stree_vlist` (packed
  index lists), `stree_save`/`stree_savenum` (original geometry of movable objects).
- **Stunts**: `gStuntPlayer[4]` (public scores) and `gStuntInfo[4]` (0x7C on the N64: an `active` bit word,
  accumulated angles `stuntW[4][3]`, timers); per-frame scratch `stunt_j/l/r/f/b` (wheels off the ground), `stunt_chW*`
  (axis sign changes), `stunt_okToStart`, `stunt_GCabsW`.
- **Smoke**: `gSmokeList` pool over `gSmokeObjs` (100 × 88 bytes), `gCarSmokeDir[6]` flags per car, `gFireTexs`.
- **Audio manager**: command slots `audiomgr_gCmds[128]` under the lock queue `audio_lock_queue`, posted to `audio_command_queue`
  (field map `tAudioMsg`: `hdr.cmd` at +2, arguments from +4); fx tags `gFxTags` with free/playing/interrupted lists and a
  sorted tree, 6 sequences, listener (60-byte) and emitter (44-byte) pools.
- **Heap** (`memsys.c`): 32-byte block headers (magic 0xFEDCBA98, size, used, owner handle), all operations under
  `heap_lock_queue`.
- **Save data**: the N64 profile (`tPlayerProfile`, 0x30 bytes: `fileh` +8, `id` +0xC, `name` +0x14, `controls` +0x21,
  `datah` +0x2C) and its 2064-byte data (revision 16; option bytes, per-race-type settings blocks at +72/+92/+108/+128
  with `track, car, trans, carView` at +4..+7, 13 car settings of 16 bytes, stats blocks, circuit). The N64 hands out
  profile and ghost handles from fixed tables (`player_profile_handles`, `ghost_file_handles`) instead of the heap.
  Controller-pak files are `tPS_File` (pak +0x10, slot +0x11, filename +0x12, data +0x48) in `gPS_Files[4]`.
- **Text**: `gFontHeader`, `gFontLetters`, `gCharMap`, the current colour/position/spacing (`gFontColor`, `gFontXpos`
  …), `gJust` (justification), `gFontColors` and the flash colours; strings starting with 0xFF are two-byte text.
- **Controls**: per pad `gContEdges`/`gContLevels`/`gAutoEdges`/`gContStick`, the OR over active pads
  (`gActiveEdges` …), under `controlsys_lock_queue`; players' copies in `gPlayers` (`gPlayers`).

## 5. Who calls whom

- `UpdateFrame` (end of every frame) → `UpdateFrameTimer` (UpdateFrameTimer) → `UpdateRushControls` → `UpdateControls`
  → `PotRange`; then `HAL_CallOncePerFrameFuncs` (`TB_TextOncePerFrame` is installed there by `TB_SetTextColor`).
- `updateGameState` → `initGameState`/`uninitGameState` (`LoadFrontEndWaves`, `HAL_PurgeFonts`, `AudioInit`,
  `AudFree3D`, `LoadFrontEndOverlay`, `SetOptions`, `PurgePlayerData` …) and the per-state update functions elsewhere.
- `LoadTrack` → `initTargetStructs`, `SkyInit`, `LoadCars` (→ `car_palette_init`), `InitCheckpointData`
  (→ `ReadCheckpointData`), `InitPathData` (→ `ReadPathData` → `SyncCheckpointsToPaths`, `SyncAltPaths`,
  `CalcResPathBounds`, `CalcCheckpointTimes`), `InitDemoPathPoint`, `InitSmoke`, `InitTextureAnimation`.
- Per race frame: `UpdateCameras` → `SkyUpdate`, `UpdateHUDPostCamera` (→ `animCoins`), `ShowCountdown`;
  `CheckForStunt`; `UpdateSmoke`; `TextureAnimation`; per car `dotireforce` (→ `frictioncircle` → `calcalpha`),
  `TireSurf`, `CollideCarBody` (→ `CollideCarBodyAgainstSurface`, `CarApplyCollision`, `PointInSurf`),
  `CheckTargetCollision`, `TargetPathAvoid`; path targets animate through `AnimatePathTarget` (an environment visual
  callback) → `PlacePathTargetPos/Quat` → `MoveCollisionObject`/`RotateCollisionObject` and `_Play*Sound` →
  `AudUpdateEmitter` and friends.
- Respawn: `AbortCar` → `CrashedStunt`, `SetResurrectionData` → `FindSurfaceUvsFromResPoint`, `SetDroneResPathIndex`
  → `NextPathPt`, `SetNewPathIndex`.
- Save: the pak server `SaveServer` (→ `NewGhost`, the inlined ghost header reader), `ReadPlayerData`
  (→ `CheckAndRepairPlayer`, `SavePlayerControls`), `CreatePlayer` (→ `NewPlayer`, `InitPlayer` →
  `SetDefaultControls`, `SetDefaultCarSettings` → `SavePlayerCarSetting`, `GetDefaultOption`, `SavePlayerOption`,
  `SavePlayerCar(View)`), ghosts (`SaveGhost`, `CompressGhost`, `ReadGhostData` → `ReadGhostDataInternal` →
  `heap_move_block_low`, `DecodeGhost`).

## 6. N64-only parts (no MAT3 counterpart, or a different body)

- **libultra semaphores**: controls, heap, fonts and the audio manager lock with `osRecvMesg`/`osSendMesg` on message
  queues where MAT3 has `_GetSemaphore`/`_ReleaseSemaphore`; their residues are the `_*Semaphore*_stub` functions.
- **Scheduler handshake**: `UpdateFrame` sends the 2750 end-of-frame request to the scheduler and drains its reply
  queue (MAT3's `UpdateGraphics`/`EndGraphics`/`StartGraphics`); the three flag bytes and two queues it uses are
  named `sched_*` (likely; they belong to the scheduler's area).
- **RSP display lists**: `displaylist_set_texture_image`, `displaylist_get_texture_image` and
  `displaylist_set_tile_size` walk F3DEX2 lists for `G_SETTIMG`/`G_SETTILESIZE` (texture animation on the N64 is
  done by patching display lists).
- **Audio thread**: `AudioInit` creates the audio manager thread (`audio_manager_thread`, entry `audio_manager_thread_entry`) and its queues; every command is a
  slot posted to `audio_command_queue`; `AudFree3D` frees the 3D pools (MAT3 never frees them).
- **Controller Pak**: profiles and ghosts are pak files (`PS_*`, `gPaks`, `SaveServer`), fixed handle tables,
  `save_file_pak_ready`, `CreatePlayer`'s unique file names.
- **Overlays**: `LoadFrontEndOverlay` loads the "Start" image and unloads "Extra" (empty on the GameCube).
- **Expansion Pak**: `expansion_pak_present` gates the extra waves, the fire textures of `InitSmoke` and part of
  `InitTextureAnimation`.
- `car_palette_init` (512-byte car palettes shared when the heap is short), `heap_total_free`, `heap_move_block_low`
  (handle compaction), `loading_effect_none`.

## 7. What is uncertain or unidentified

- **Stub assignments** follow the reverse-call-order rule and are `likely`: the three save setters'
  (`_SaveObstacle/Stunt/BattleSetting_stub`), `video_uninitButtons` (the decomp's body for it is `RemovePanes(0)`, a
  matching device), `InitLL_stub`, `GetUniqueExtension_stub`, `matf2scopy_stub`, `InitCameras_stub`, `TB_TextInit_stub`.
  For the getters at 0x800B4AE8..AF8 the C bodies (battle, stunt, obstacle) decide the names, though the layout rule
  would put obstacle first.
- `ZOID_SetObjectDef_TargetPaths` (0x800C15FC): the decomp's inlined copy of `ZOID_SetObjectDef`; the retail stub there
  is most likely `_PlaceGhostRacePath`'s.
- No MAT3 counterpart, named from the code: `car_palette_init`, `heap_total_free(_unlocked)`, `heap_move_block_low`,
  `AudFree3D`, `save_file_pak_ready` (no caller in the C), `loading_effect_none`, the three display-list walkers.
- Data named from the code and marked `likely`: the scheduler flags/queues, `screen_width`/`screen_height`, the six state-1
  flags (`gGameStarted` … `lcdInited`, mapped by MAT3's order), the coin counters (`gGoldCoinCnt` and siblings: gold
  versus silver is by the chained-assignment order), the car default colour bytes, `rear_traction_by_*`,
  `video_resetChoice`, `video_dither_filter`, the profile/ghost file strings.
