# Area r2: the game image from 0x8009DC50 to 0x800B4720

This is the map of one slice of the game image (258 functions, about 90 KB of code), written for a programmer new
to the game. The names are the ones proposed in [`tools/port/names/r2.tsv`](../../tools/port/names/r2.tsv); the old
label follows in brackets where it helps to find the code today. Where a name comes from the MAT3 GameCube decomp
(the same game from its debug executable) the MAT3 source file is given, so you can read the original logic there
(`decomp/src/GameSource/src/<file>`).

## 1. What this part of the game does

Almost nothing here is driving physics, whatever the old labels said (`car_crash_response`, `traction_control`,
`engine_torque_calc`, `cpak_init` ... were early guesses). The slice holds the game's plumbing between the race code
and the hardware:

- **the N64 renderer back end** ("zoid"): the scene-graph walk that turns the object tree into RSP display lists,
  window (viewport) set-up and split-screen layouts, flat polygons and 2D blit instances, world visibility culling
  and fog;
- **the Controller Pak file system** (`paksysdc.c`, N64 `osPfs` form) and the Rumble Pak switches;
- **the overlay loader and the N64 heap** (allocate at an address, compaction);
- **the world and target loaders**: the world object tree of a track, the interactive track objects ("targets"),
  the road spatial tree (`stree.c`): quadtree lookup, path interpolation, shot/segment collision against the road;
- **car visuals**: creating a car's display objects, sparks, wings, blasts, sheen, colours, skid marks, the
  environment visual list;
- **audio glue**: the sound system start/stop (the N64 MusyX driver underneath), the sound-effect queues, 3D
  emitters, the text and font waves;
- **text**: font set-up and text width (`HAL_text.c`), the per-language text wave, panes (bordered boxes made of
  five blits), the 2D blitter state, and a small C library (string functions, memmove, a checksum).

36 of the functions are 8-byte `jr ra; nop` stubs in the retail image: the deleted bodies of static helpers that
`umerge` inlined into their callers. Ten of them have the helper's body written under the stub's label in some
group (so the C has a real function of that name): `unload_wave_if_matching`, `_ReplaceWaveInstance`, `_ConvertHeap`,
`set_target_data`, `get_world_part_flags`, `_GetSkid`, `_ContinueSkid`, `MakeRamps` and the two font-lock helpers.
The other 26 are bare: they have no callers and do nothing, only marking where the static sat. Four are named after
the known helper (`world_distance_stub`, `pak_get_handle_stub`, `bg_load_wave_check_stub`, `remove_visuals_stub`),
the rest `<module>_stub[_letter]`. On the PC the bare ones can simply go.

## 3. Main data structures

All sizes and offsets are the N64 ones (the PC copies of some records are wider: see the `PC_*` macros and
`docs/port/POINTERS.md`).

- **Scene nodes, `ObjInstanceList`** (`D_8012E700`, 0x44 bytes each; MAT3 `anon_flags_culling_60`): `flags` (+0;
  bit 0x80000000 hidden by WorldCullObjects, 0x100 << view hidden for one window, 0x40000/0x800000 deferred passes,
  0x8000 upright, 0x10000 scaled), culling word / culling-box vertex index (+4), `mat` (+8, a `tUVMatrix`: 3x3
  rotation then position at +0x24), `scale` (+0xC), `w` (+0x10), model id (+0x14, `index >> 10` = model table,
  `& 0x3FF` = object), `child` / `next` (+0x16/+0x18, -1 ends), `numLights` / `lights` (+0x1A/+0x1C), `texture[4]`
  (+0x20), `tile` / `tileSize` (+0x30/+0x34), `palette` (+0x38), `color` / `envcolor` (+0x3C/+0x40). `ObjHead` is
  the first root; `gNumObjects` the count.
- **Windows, `ZoidWinInfo[4]`** (`D_8017A510`, 0x48 bytes; MAT3 `tWindowInfo`): viewport and scissor pointers,
  angles and their tangents, width/height/centre, front/back clip, fog min/max (+0x40/+0x42) and colour (+0x44).
  `gNumZoidWindows` and `gSplitScreen` describe the layout; `vp0`..`vplr` and `scissor0`..`scissorlr` are the
  per-layout viewports and scissors.
- **Polygons and blits**: `PolyInstanceList[200]` (MAT3 `tPoly`: nverts, flags, texidx, `z` at +6, four vertices)
  and `gBlitInstanceList[200]` (32 bytes; `hide == 2` marks a free slot; old name `pad_config`). Above them sit the
  game-level blits (`Blits[200]` through `BlitPtrs`/`NumBlits`, MAT3 `_tBlit`) and the panes (`gPaneBlits[16]`, five
  blits each: fill and four borders).
- **The blitter state** (`blit_pc.c`): `blitAttribute`, the scissor `blitXmin`..`blitYmax`, `blitZDist`, `blitMode`,
  `blitLUT`, `blitColors`, the two alternating display lists `blit_display_lists` and their cursor `blitDL`.
- **World tree** (`world.c`): `WorldTable` (sorted name table, searched with bsearch), `WorldBase` (104-byte
  `tModelPart` nodes: matrix, flags, next/child, bounding box), `Worlddlidx`; per-track zone visibility rows
  `track1Parts`..`track19Parts` (four 32-bit words per zone), `trackParts` (zone counts), `showAllParts`; fog tables
  `fogMin`, `fogDistance`, `trackFog` and `gFogIntensity`.
- **Road spatial tree** (`stree.c`, set up by `InitSTree` from `gRoadDat`): `gRoadHead` (counts), `gRoadPath`
  (132-byte path segments: position, basis, widths), `gRoadSTree` (20-byte quadtree nodes: box, child per quadrant,
  leaf mask), `gRoadSurf` (24-byte surfaces), `gRoadSVert` (8-byte packed vertices), `gRoadSave` (movable surfaces,
  MAT3 `savetyp`), and the run-length lists `gRoadVList`, `gRoadSList`. (MAT3 calls them `stree`, `surf`, `svert`,
  `path`, `save`, `vlist`, `slist`; the `gRoad` prefix avoids clashes with common local names.)
- **Targets** (`targets.c`): `gTargetInfo[122]` (48-byte per-name records: category, flags, start/animate functions),
  the target nodes in `gTargetList` (a `tStatList`), the per-category struct pools `gTargetStructPtrs` /
  `gTargetOwnStructPtrs` / `gTargetStructCount` / `gTargetStructSizes`, the bounding-box models `gBBoxModelStructs`
  (`tMiniModelData`: uvs +4, pos +0x28, vel +0x34), `gTargetPaths`.
- **Controller Pak** (`paksysdc.c`): `gPaks[4]` (772 bytes each: the MAT3 flag bytes `changed`, `inserted`,
  `damaged`, `flushing`, `flush` ..., the `OSPfs`, the error, `FreeSpace` at +0x78, the rumble bytes at +0x7C..,
  then 16 directory slots of 40 bytes: flush flags, dirty-map size, the `OSPfsState`), `gPS_Files[4]` (a `tDLList`
  of open file handles per pak), the 64 handles `pak_file_handles` pointing at `pak_file_records` (N64 `tPS_File`,
  76 bytes, `size` at +0x40), the free list `pak_free_handles`, and the callback `gErrorFunc`. Each open file keeps
  its data followed by a dirty bitmap (one bit per 32 bytes); `PS_WriteFile` marks pages, `_PS_FlushFile` writes the
  dirty runs.
- **Waves and text**: `gWaveInstance[64]` (20 bytes: loaded, ready, locked, model, mirrored, handle, wave, size,
  `ptr` +0xC), `gText` (the six tables of the language wave), `gLang`, `gTextWave`, `gTextWaveInst`; the font state
  `gFontHeader` (ascent +2, descent +3, leading, spacing, `nonProp` +9), `gFontLetters`, `gCharMap[256]`,
  `gFontTextures`, `gLeading`, `gSpacing`, `gFontIndex`.
- **Car visuals** (`visuals.c`): `gCarParts[52]` (0x40 bytes: frame, three rocket parts, hood, sheen, weapon, four
  tires, five sparks), the per-car `tCarData` (`gGameCar`, 0x3B8 bytes: appearance +0xE8, objnum +0xF4,
  `visuals[21]` at +0x110 (one fewer than on the GC, so later fields are 0x18 lower than MAT3), view +0x35D,
  roktScale +0x374), the environment visuals `gEnvirons[100]` / `gEnvList` / `gFreeVis` (MAT3 `tVisual`, 0x18 bytes:
  next, objnum +6, slot +8, func +0x14), `gObjList` (model ids by role), `gTexList`, `gWheelTextures`.
- **Skids**: `gSkidList` / `gSkidArray[100]` / `gNewSkid[6][4]` (MAT3 `skids.c`).
- **Heap** (N64 `memsys`): 32-byte block headers in a doubly linked list per heap (size, owner handle, used, tag,
  lock count, magic 0xFEDCBA98), guarded by the `heap_lock_queue` message queue.
- **Audio**: `gSfxInstances`, `gSfxCmds`, `gSfxFreeQ`, `gSfxCmdQ` (MAT3 `audiosfx.c` statics), emitters
  `gEmitters` / `gFreeEmitters` / `gActiveEmitters`, the queues `audio_lock_queue` and `audio_command_queue`.

## 4. How the functions call each other

- **Frame draw**: `ZOID_EndFrame` -> for each window `zoid_draw_window` -> `WorldCullObjects` (zone rows of the camera
  position) -> `Traverse` (recursive, `zoid_node_visible` / `zoid_subtree_visible`, culling boxes, display lists via
  the old label `particle_system` at 0x8009C8F0, in the area before this one) -> the flat polygons; then the 2D blit instances through the blitter
  (`BlitInit`/`BlitFinish` open and close the 2D display list). `ZOID_ProjectWindow` / `ZOID_WindowTo3D` convert
  between world and screen; `WorldFogDensity` sets a window's fog per frame.
- **Race start**: `InitVisuals` (car part ids, rim and skid textures) -> `InitTrackDynamicObjs` (effect/weapon/wing/prop
  ids) -> `SetTargetDefs` -> `SetTargetDef` per target; the world tree comes from `NewWorld` -> `NewWorldObject`
  (recursive; `SetupTarget` for interactive objects, `MBOX_NewObject(Cam)` for scenery, `ZOID_BuildCullingList` for
  zone boxes) -> `InitSTree`. `StartEnvironment` runs `CreateCar` + `StartCar` (`StartFrame`, `StartSparks`,
  `StartWing`, `StartWingFlame`, tires) for every car, then shadows and arrows.
- **Per frame per car**: `UpdateVisuals` -> each visual's function, `UpdateSkids` (`_StartSkid` / `_ContinueSkid` /
  `_StopSkid`); `UpdateEnvirons` -> environment visuals, `AnimateSkids`.
- **Road queries**: `updownleaf` -> `downleaf` find the quadtree leaf; `ShotToWorldCollision` walks leaves along a
  segment and tests each surface with `CylinderInSurf` (`DecodeVlist`, `VectorToSurfEdge`); `fPathInterp` /
  `fHalfPipeInterp` give a position's frame on a path segment (`surfpos`, `FVecInterp`, `fpitch`, `froll`).
- **Controller Pak**: `PS_InitPakSys` once; `PS_PakServer` each frame (insert/remove, same-pak detection, directory
  read); the save code calls `PS_CreateFile`, `PS_ReadFile` -> `PS_ReadPartialFile`, `PS_WriteFile`, `PS_FlushFile`
  / `PS_FlushPak` -> `_PS_FlushFile`, `PS_DeleteFile`; errors go to `gErrorFunc` (the pak error dialog) with retry.
- **Audio**: `AudioInitSys` (threads, `InitWaves`, sound waves, driver start, `AudioSfxInit`) / `AudioShutdownSys`
  (`audio_sfx_shutdown`, `stop_current_song`); `EmitGameSound` -> `AudEmitEffect` -> `_NewEmitter`.
- **Text**: `HAL_SetFont` -> `_HAL_SetFont` -> `_SetupFontData`; `HAL_GetTextWidth`, `TB_GetFontLineHeight`;
  `InitTextWave` / `LoadTextWave` -> `ReplaceWave` -> `_AdjustTextWavePointers`.
- **Overlays**: `load_start_overlay` / `load_extra_overlay` -> `load_overlay` -> `allocate_memory_at`, inflate, clear
  bss; `unload_*_overlay` free the block.

## 5. N64-only parts (no MAT3 counterpart)

- libultra: `osPfs*` (file state, read/write, allocate, delete, free blocks, init, repair id), `osMotorInit` and the
  motor access (rumble), `OSContStatus` polling (`pak_poll_inserted`), threads and message queues used as locks
  (`heap_lock_queue`, `pak_lock_queue`, `audio_lock_queue`, `gFontSem`), cache writeback/invalidate.
- The RSP/RDP display-list code: `Traverse`, `zoid_draw_window`, `ZOID_EndFrame`, `BlitInit`/`BlitFinish`,
  `mtx_rotation_to_fixed` (s15.16 `Mtx`), the culling boxes (`gSPCullDisplayList`), `zoid_frame_gfx`.
- The Controller Pak character codec (`pak_encode_name`, `pak_decode_name`, `pak_charset`), the dirty-page writes
  (`pak_find_dirty_run`, `pak_mark_dirty`), `pak_error_from_pfs`.
- The overlay loader and the heap allocator/compactor (`allocate_memory_at`, `ClearMemoryHeap`).
- The MusyX driver start (`AudioInitSys` hands it `musyx_project`, `musyx_sdir`, `musyx_pool`, `musyx_samples`),
  `audio_sfx_shutdown`, the background wave loader thread (`BGLoadWaveMain`).
- `update_player_visibility` (battle-mode line of sight), `zoid_scale_windows`, `zoid_set_window_count`.

## 6. Not identified, or only partly

- 22 of the 26 bare stubs are named only by module; which static each one held is not known (zlib's five are among
  `copy_block`, `build_bl_tree`, `send_all_trees`, `read_buf`, `tr_static_init`).
- Names from the GC debug information that this tree cannot show (stripped on the GC, cited by the file headers of
  the matching agents): `ClearMemoryHeap`, `BGLoadWaveMain`, `MakeRamps`; marked likely.
- `ZOID_EndFrame` and `Traverse` are the GC back end's names for the same roles; the N64 bodies are different code.
- `PS_SetRumblePercent` (no caller left in C), `PS_PakFormatted` (returns 1), `AudioSongInit`, `AudioShutdownSys`
  are matched by role and position, not by body.
- Data named by role only, likely: `gDummyVtx`, `night_car_colors_a/b`, `blit_ia_palette`, `blit_tile_lines`, the
  `zoid_late_*` pair of deferred-pass flags, `audio_low_memory`, `gSongNumber`, `all_tracks_open`, `track3Parts` ..
  `track19Parts` (MAT3 has only the first two tables), `RimNames`, `tire_object_names`.
- 77 labels in `asm/us/blob/symbols.json` inside this range are not function starts (guesses at round or
  mid-function addresses such as `InitDrones`, `DoDrones`, `MaxPathControls`, `car_velocity_clamp`), and 5 more are
  second names of a function (`render_scene`, `physics_velocities_P`, `audio_channel_free`, `object_helper`,
  `object_utility`); the map lists both kinds for removal.

## 7. Things that look like bugs (all original behaviour; the PC build keeps it)

- `InitPane` returns `&gPaneBlits[16]` (one past the array) when all 16 panes are in use, and its callers write
  through it (MAT3 does the same).
- `RemoveBlit` on a blit that is not in `BlitPtrs` (a double remove) still decrements `NumBlits` and swaps entries,
  corrupting the table. `NewMultiBlit` and `InitPane` use `NewBlit`'s result without checking for 0 (pool full).
- `SetSheen` leaves its camera mask uninitialised for a player outside 0..3 (no `default:`; MAT3 too).
- `pick_random_masked_bit` never returns for an all-zero mask.
- `allocate_memory_at` has an empty "does not fit" test: an overlay larger than its block overruns silently.
- `ZOID_NewMatrix` increments `gNumMatrices` with no bound (index 0 is never used).
- `update_player_visibility` also tests every car against itself and every pair twice (harmless, wasted work).
- `_CalcChecksum` reads unsigned bytes on the N64 and signed ones on the GC, so the two save checksums differ.
