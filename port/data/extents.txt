# N64 sizes of data symbols, for tools/port/gen_data.py, where the C declarations leave the size open (T x[]) or
# get it wrong. Without one, an incomplete array runs to the next known address, which can swallow tables no C
# declares yet, and a declaration that runs over the next object makes that object part of its storage. A size
# here wins over the gap and over the game C's own definitions (the symbol file's size: comments still win over
# this): longer array declarations are cut to it, and declarations of exactly this size are preferred. Format:
# name size. Better still: give the C declarations their size, then drop the line.

# The file table (docs/port/ASSETS.md 2.2): 183 entries each; the next table starts after.
wave_rom_offsets 0x2DC    # ROM offset, u32[183]; track 1's PVS starts at 0x8011B898
gWaveSizes 0x2DC    # size in RAM, u32[183]; gLargestTextWave follows
wave_storage_kinds 0x2DC    # storage kind, s32[183]
wave_is_model 0xB7     # model flag, s8[183]

# Declarations that run over the next object. Each swallowed globals into its own storage, where the ones with
# pointers overlapped their neighbours (data_layout.txt lists any left under "Inside own storage, but ...").
gResPath 0x10     # gResPath {numPts, pts, numAlt, alt}: gGhostToSave (GhostHeader *) is at +0x10. The 28-byte
                    # Header/PGraph views were written to the PC layout (ReadPathData's 32 bytes)
gRealNewGhostHeaders 0x160    # the ghost headers, 4 of 0x58 (GhostStart: gNewGhostHeaders[i] = &gRealNewGhostHeaders[i], i < 4), not 1
gInterruptedFxTags 0x10     # a 16-byte list head (List, tDLList); ap.c's 20-byte Node runs into pak_file_handles (PakHandle[])

# The level-object node pool's elements (docs/port/POINTERS.md 10): 130 nodes of 0x70 bytes, which keep their N64
# layout in the arena (initTargetStructs's pool_init). collision' Vehicle2056 view only takes the address
# (the end of the model array), and its 0x808-byte elements left the extent at 7 of them.
gTargetArray 0x38E0
# Sizes the game C's tentative definitions gave, which are declarations on the PC (PC_ONLY(extern): Windows' code
# can't reach a symbol in the RDRAM window PC-relatively, docs/port/WINDOWS.md).
gJust 8        # the TB_SetJust pair (gJust), coins.c, controls.c, countdown.c, audio_animPanes_demo_animText.c, videoscr.c
blit_cache_tile 8        # s64, blit_load_texture.c (both copies)
gDriveHulk 4        # s8[4], InitOptions.c
gContStickRange 8        # s8[4][2] (gStickCal), InitControlSys.c
D_8014A250 0x3030   # Car[6] of 0x808, init_cars.c
# Tables the code indexes past their declaration (tools/port/index_check.py, docs/port/SYNTH.md 3): the car tunes,
# three 44-byte Tune44 records (CalcMass reads ((F2C *)&gTune_weight_scale)[tune], gTune_weight_scale being record 0's +4; the
# declarations leave one record, and the other two kept the ROM's byte order).
gTune 0x84
# The cars' drag, f32[5][3] by traction type and tune (CalcDrift reads ((f32 (*)[3]) &gTireDrift)[i][j]; its
# TARGET_PC declaration gives the table; the gap to gTireSideForce is its size).
gTireDrift 0x3C
# gSongNames: the twelve songs' names (audio_calcMenuRect reads [0..11], the audio screen [audio_gSong]). By the gap
# the declaration ran 131 pointers to the next known address, so the loader turned 119 words of whatever follows into
# pointer slots of its own storage.
gSongNames 0x30
# The track animations' pointer tables (TextureAnimation, InitTextureAnimation): one per track, 19 (gTrackNum 0-18). By
# the gap they ran over the palette animations after them, which port/data/reached.txt now converts.
TextureSwapLists 0x4C
PaletteLists 0x4C
# The gear ratios, f32[8][6]: a row per car class (the model's byte 9), the ratio of gear g at [g + 1]
# (transmission reads them from carTransGearRatio_biased, its +4, by byte offsets; tools/port/index_check.py). By the gap the
# table was one row, and the rows after it kept the ROM's byte order: a battle car's drive torque came out absurd and
# its wheels never turned.
carTransGearRatio 0xC0
# The player screens' model slots (image A, Slot64[players][22]: unknown0 picks the model name): four players. A
# known address 0x1080 in left the extent at three, and the fourth player's slots kept the ROM's byte order (a
# four-player game faulted on its model names). The table ends at playerscr_gButtonZoom; gPlayerRects_biased's row 0, which is never
# read, lies in its last 16 bytes.
playerscr_buttonInfo 0x1600

wingOffsets 0x9C     # f32[13][3], per car type (AnimateWing, the wings; wingOffsets_y is its [0][1]); D_8011B550 follows
gravityArray 0x10     # gravityArray f32[4] (PrePlay: by the gravity option); by the gap it ran over strings
